# Jules AI Integration Guide

This guide explains how to use Jules AI with the Ashle cloud kitchen management system.

## Quick Start

### 1. Enable Jules on Your Branch

Jules is configured in `julius.config.yaml`. All tasks will run automatically based on:
- **Schedules** (daily, weekly, bi-weekly)
- **Push triggers** (when specific files change)
- **Manual requests** (via API or CLI)

### 2. Available Jules Tasks

#### Test Generation
**What it does:** Analyzes your code and generates comprehensive test cases

```bash
# Trigger manually (coming soon)
jules task run generate-tests
```

**Automatic triggers:**
- Weekly schedule
- On push to `src/inventory/*`
- On push to `src/orders/*`

**Example output:** Jules will create PR with:
- Edge case tests
- Integration tests
- Performance tests
- Error handling tests

#### Performance Optimization
**What it does:** Finds N+1 query problems, missing indexes, and slow operations

```bash
# Trigger manually
jules task run optimize-queries
```

**Runs:** Bi-weekly + on-demand

**Example output:** 
- Fixed database queries with indexes
- Added query caching
- Optimized API response times
- Updated query documentation

#### Documentation Updates
**What it does:** Keeps your code documentation current

**Automatic triggers:**
- Weekly schedule
- On every push to `src/`

**Output:**
- Updated API documentation
- Code comment improvements
- README updates
- Architecture diagrams

## How Jules Creates Pull Requests

1. **Jules works in the cloud** (doesn't block your development)
2. **Analyzes your code** and identifies improvements
3. **Makes changes** and runs tests
4. **Creates a PR automatically** with:
   - Clear description of changes
   - Labels: `ai-generated`, `auto-pr`
   - Linked to original issue (if applicable)
5. **You review and merge** at your own pace

## CI/CD Integration

Jules is integrated with GitHub Actions in `.github/workflows/julius-ci.yaml`

### Workflow

1. **Push code to your branch**
2. **GitHub Actions runs:** tests, lint, code quality checks
3. **Jules kicks off** based on triggers in `julius.config.yaml`
4. **Jules creates PR** with improvements
5. **CI runs on Jules PR** to validate changes
6. **Jules auto-fixes** if CI fails (new feature!)

### Auto-Fix Loop

If a Jules-generated PR fails CI:

1. Jules receives the error
2. Analyzes what went wrong
3. Applies the fix
4. Re-pushes to the same PR

**You never have to fix Jules's mistakes!**

## Customizing Jules Tasks

Edit `julius.config.yaml` to:

### Change Task Schedule

```yaml
tasks:
  - name: "generate-tests"
    triggers:
      - schedule: "daily"  # Change from weekly to daily
```

### Add New Trigger

```yaml
tasks:
  - name: "optimize-queries"
    triggers:
      - on_push: "src/database/*"  # Run whenever database code changes
```

### Create New Task

```yaml
tasks:
  - name: "refactor-old-code"
    description: "Modernize legacy code patterns"
    modules:
      - src/legacy/
    priority: low
    triggers:
      - manual  # Only run when explicitly requested
```

### Protect Sensitive Modules

```yaml
rules:
  - dont_modify: ["src/payment/", "src/auth/"]  # Jules won't touch these
```

## Troubleshooting

### Jules PR Not Being Created

1. Check `julius.config.yaml` is valid YAML
2. Verify triggers match your git activity
3. Check `JULES_API_KEY` is set in GitHub secrets
4. View workflow logs in GitHub Actions

### Jules PR Failing CI

Jules will automatically detect and fix failures, but if it happens repeatedly:

1. Review the Jules PR comments for error details
2. Update the module if there's a constraint Jules doesn't know about
3. Comment on the PR to provide guidance
4. Jules will learn from feedback

### Don't Want Jules to Modify Something

Add to `julius.config.yaml`:

```yaml
rules:
  - dont_modify: ["src/your-sensitive-code/"]
```
